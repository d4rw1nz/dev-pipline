# 接入现有项目

先核实当前结构与历史，再确定需要调整的职责。只要求分析时交付结论与建议；获得实施授权后继续修改和验证。

## 了解现状

读取项目规则、需求、依赖、生成方式、构建和 CI。沿实际入口追踪调用、数据写入与生命周期，检查工作区改动及相关测试结果。

查阅功能引入、重构、合并、回退和历史修复，关联必要的 Issue、PR 与设计说明。区分语言或框架要求、业务职责和历史习惯，改动范围由实际问题决定。

## 记录结论

按需要更新同主题文档：

- 研究：当前结构、关键调用与数据流、相关提交、问题及未知事项。
- 设计：目标职责、方案差异、调整对象、调用方与实施顺序。
- 项目说明：实施后的目录、入口和模块职责。

持续跟进的事项写入 Issue，链接必要文档；验证结果直接记在任务或交付回复中。每项主要变化说明解决的具体问题，并核实调用方与数据影响。

## 实施与验证

需要接入规则时，按 [AGENTS.md 写入规则](documentation.md#agentsmd-写入) 将模板固定内容合入项目文件，保留已有约定。只读分析按现有规则进行。

确认可运行的检查入口和复现方法，再按职责调整实现、调用方、测试、文档与构建，清理被替换的路径。

每项改动围绕清楚的目的，保留其他工作区修改。确需隔离时使用 worktree。修改后执行适用验证，按 [复审规则](quality.md) 检查依赖、数据写入与生命周期是否符合目标。
