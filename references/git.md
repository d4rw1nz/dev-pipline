# 中文 Git 提交与 PR

采用 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/zh-hans/v1.0.0/) 的结构。规范核对日期：2026-10-19。以下中文说明、类型选择和提交粒度是本工作流的约定；不将 Git 提交本身等同于发布授权。

## 用 Git 历史理解项目

修 bug、调整架构、删除接口或替换状态规则前，查看相关提交图、分支关系、引入、合并、回退和历史修复，关联当时的 Issue、PR 和设计说明。目的是理解原因与已试方案，不是机械复制旧实现。

先 `git status --short` 和当前 diff 确认现场，再按问题查 `git log --graph --decorate --oneline --all`、`git log --follow -- <路径>`、`git show <提交>`、`git log -S <符号> -- <范围>` 或 `git blame`。路径与用户输入按参数正确引用，不拼 shell。不要一开始读取整个仓库所有历史；先从相关功能和关键改动逐步扩展。

blame 只说明某行的最近归属，不能单独证明根因；文件移动、合并及回退需要看完整上下文。浅克隆、缺分支、缺 Issue 或未提交变化导致信息不全时注明，先获取获授权范围内必要信息，不臆测原设计理由。需要定位回归区间时可在隔离 worktree 做 bisect，不改变用户工作区或日常服务。

研究与计划记录真正影响判断的提交和行为变化，当前未提交源码另外注明。历史事实不自动成为现行需求，也不能因已有兼容层就继续保留它。

## 保持可追溯的提交关系

提交与 PR 关联稳定 Issue，正文说明非显然的原因、行为和验证，文档链接保留关键决定。一个目的一个提交，必要测试与实现一起保持可检查；无关格式化不混入根因修复。合并或 squash 按项目策略保留最终理由与 Issue 关联，不擅自改写共享历史。

worktree 用于确有隔离收益的并发或历史复现，不等同于必须每个任务建分支。使用已有约定，防止提交其他人的改动；合并前检查实际差异和相关验证。

## 提交格式

```text
类型(可选范围): 中文动作与结果

必要时用中文说明原因、行为变化和验证结果。

可选脚注
```

类型保留常用英文标记，范围优先使用项目已有模块名，标题、正文和不兼容说明使用中文。标题使用明确动作，不写“更新一下”“修复问题”等无法判断内容的文字。

| 类型 | 适用变化 | 示例 |
| --- | --- | --- |
| feat | 新增用户或调用方能力 | `feat(search): 支持按标签筛选结果` |
| fix | 修正错误行为 | `fix(auth): 合并并发请求触发的令牌刷新` |
| refactor | 调整结构且不改变预期功能 | `refactor(storage): 统一会话存档的写入职责` |
| perf | 有性能目的的优化 | `perf(images): 缓存已解码的缩略图` |
| test | 添加或修改测试 | `test(queue): 覆盖取消与重试的执行顺序` |
| docs | 文档变化 | `docs: 补充本地开发和验证命令` |
| build | 构建系统和依赖 | `build: 固定打包工具版本` |
| ci | 持续集成配置 | `ci: 添加单元测试覆盖率报告` |
| style | 不影响逻辑的格式调整 | `style: 统一文件缩进` |
| chore | 其他维护事项 | `chore: 清理失效的工具配置` |
| revert | 撤销已有变更 | `revert: 撤销未完成验收的导入流程` |

一个提交围绕一个可解释的目的，修复与必要回归测试可以同一提交；实现与测试分工不要求机械拆成不能独立检查的提交。无关重构、格式化、依赖升级分别提交。不以“重构”掩盖实际产品行为变化。

## 不兼容变更

对于会影响调用方或数据使用方式的不兼容变化，本流程同时使用 `!` 和 `BREAKING CHANGE:`：

```text
feat(config)!: 改用单一服务配置格式

更新受控调用方和配置校验，删除旧字段解析。
验证：配置单元测试与导入失败回归通过。

BREAKING CHANGE: 不再接受旧版服务字段，外部配置需改为新的服务列表格式。
```

说明受影响接口、调用方和必要操作。不保留旧格式是设计选择，仍须明确数据影响。普通内部变量重命名不自动成为对外不兼容变化。规范本身允许 `!` 或脚注二选一，同时使用是本流程为了可读性采取的约定。

## 提交与 PR 检查

- 提交前检查暂存差异，确保只包含本次授权范围；保留其他未提交工作，不自动执行全量暂存或改写已有历史。
- 检查凭据、本机配置、生成物和依赖目录未进入提交；保留应跟踪的依赖锁定文件。
- 相关检查按当前最终代码执行，未执行的命令不写成已通过。小提交可以只写标题，非显然的行为变化补充原因与验证。
- PR 用中文先说明具体问题和最终行为，再写重要取舍、验证结果与限制。界面变更附实际截图或说明未验证环境。
- PR 描述以最终实现为准，删除过时方案与聊天过程；不罗列没有帮助的中间尝试。
- 未授权提交时交付改动与建议提交标题；已授权则完成提交，无需再次确认。推送、合并和发布分别遵守已有授权范围。
