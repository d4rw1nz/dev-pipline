# 项目知识维护

开工查阅相关经验，工作中记录影响判断的事实，任务结束时判断是否有可复用结论。保存后核对内容与实际情况。

| 内容 | 保存位置 |
| --- | --- |
| 长期开发偏好 | AGENTS.md 或已有开发规范 |
| 产品规则与行为修正 | 对应需求，Issue 引用相关内容 |
| 根因、隐藏约束与接口问题 | 同主题研究或工程说明，关联版本与测试 |
| 可重复错误 | 回归测试、静态检查或类型约束 |
| 架构决策 | 设计文档与相关 Git 提交 |
| 临时异常 | Issue 中影响后续处理的简短结论 |
| 可复用步骤 | 项目脚本、现有开发说明或项目级 skill |

## 取舍

保存前核实事实是否可靠、是否会再次遇到、能改变什么后续行为，以及是否已有相同内容。优先更新现有规则、文档或测试；没有新增价值时省略记录。

经验说明触发条件、根因、正确做法、适用范围和验证方法。尚未证实的判断标明待验证。长期偏好按时间、适用范围和明确程度处理冲突，其他项目的规则需要单独确认其适用性。

## 任务结束

检查根因是否已解决，是否遗留重复实现、临时路径或测试盲点；已有经验未起作用时，查清是未读取、条件不清、缺少检查还是实现已变化。

有可复用结论就更新对应位置，Issue 只留必要链接。按模块、症状和相关提交查找知识，保持每个结论只有一份正文。

## 维护

记录必要来源和最近验证日期。依赖升级、职责调整或新事实出现后重新核实；替换过时说明并修正入口，保留未解决的问题。历史通过 Git 查阅，维护范围限于已授权项目。
