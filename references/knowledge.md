# 长期反馈、经验与反思

知识属于项目，不能依赖某次聊天仍在上下文。开工召回相关内容，工作中及时保存有价值事实，每个需求完成前判断沉淀价值，写后复读核实，不能只说记住了。

| 信息 | 落点 |
| --- | --- |
| 用户长期开发偏好 | AGENTS.md 简短规则或项目开发规范链接，如 Make、中文提交、不保留兼容分支 |
| 产品规则和行为纠正 | 对应需求、验收及 Issue |
| 根因、隐藏约束、接口陷阱 | 同主题研究或工程经验，关联源码/版本/适用条件/回归测试 |
| 可重复错误 | 优先转为测试、lint、类型或结构检查，经 Make/CI 执行 |
| 架构决策理由 | 计划和相关 Git 提交、放弃方案、改变决定的条件 |
| 临时异常与调试数据 | Issue 只记影响结论或后续处理的摘要；原始数据临时使用，不另建验证报告或升级为永久禁令 |
| 可复用步骤 | 项目脚本、说明或项目级 skill；跨项目推广另按授权 |

## 判断是否值得沉淀

检查证据是否可靠、是否可能复现、会改变什么后续行为、是否已有相同规则、能否自动检查。有价值则更新最近职责位置，重复合并；没有复用价值就不新增，不凑反思篇数。

经验包含触发条件、观察与根因、正确做法、适用模块/版本、验证方式、对应测试/命令及重新检查条件。不能只有“下次注意”。未经验证的猜测标待验证，不写成架构真理。

用户明确长期反馈及时保存，不能每次重新问。同类反馈冲突按时间、适用范围和明确程度核实，不留矛盾规则；项目偏好不自动扩大到其他项目。

## 每次完成后的反思

检查原假设与事实差异；根因是否已在正确职责修复；是否留下补丁/重复/临时路径/测试盲点；既有历史或经验为何未起作用；该补哪条需求、规则、测试或工具，以及下次如何召回和检测。没有新知识时简要记录理由，不写空泛赞美。

Issue 保存简短反思与链接，长期正文只维护一份。按模块、症状、规则和提交召回匹配内容，不把无关经验强加当前任务。

## 清理

记录依据和最近验证日期。升级、职责迁移或新证据出现时重查；过时条目标替代关系，当前入口只指向有效结论。优先合并、精简、可逆归档，保留来源与未解决问题。没有授权不修改个人全局 skill 或其他项目，不要求额外安装记忆服务。
