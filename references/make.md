# Make 开发入口

Makefile 为用户、agent 和 CI 提供一致的开发入口。`make help` 展示实际操作、参数与产物，具体实现由底层脚本或语言工具负责。

| 目标 | 职责 |
| --- | --- |
| help | 展示可用操作、必要参数和文件修改行为 |
| setup | 准备锁定依赖与项目工具 |
| dev/build | 开发与正式构建，说明平台及产物 |
| format/lint | 分别提供格式化和只读检查 |
| test/coverage | 按模块或任务执行测试与覆盖率统计 |
| check | 静态检查、文档与架构约束 |
| verify（按需） | 组合实际需要的测试、检查和构建 |
| clean | 清理可重建产物，保留任务、业务数据和未提交文件 |

按项目实际能力提供目标。Git 使用标准命令，Issue 直接读写 Markdown；提交与发布使用独立入口并遵守授权。

已有可靠脚本由 Make 调用，README 与 CI 指向相同入口。帮助说明与目标同步，合理使用 `.PHONY`，保证依赖顺序与失败退出码。共享输出需要支持所采用的并行执行方式。

参数作为数据传递，校验必要的标识、路径和枚举，避免将外部文本作为 shell 执行。长时间运行的服务显式启动与停止；生成文件按项目输出约定管理。采用目标平台支持的 Make 语法，平台差异放在对应脚本中。

首次接入核实 help、正常路径、失败传播和实际使用的并行方式。README 记录可运行命令与版本，未验证的操作明确标注。

普通任务遇到尚未采用 Make 的项目时，先使用可靠的现有命令完成工作，按范围补充必要入口。完整迁移在 init/adopt 的授权范围内推进；只读分析与文档任务保持对应范围。
