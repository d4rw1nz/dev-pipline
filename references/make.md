# Make 统一开发入口

Makefile 是项目对用户、agent 和 CI 的公开入口。make help 展示真实操作、参数及产物；底层脚本和语言工具负责具体实现，不把大量业务逻辑塞进 Makefile。

| 目标 | 职责 |
| --- | --- |
| help | 展示实际目标、必要参数、是否修改文件 |
| setup | 准备锁定依赖和工具，不隐式修改全局环境 |
| dev/build | 开发与正式构建，明确平台与产物 |
| format/lint | 格式化与只读检查分离 |
| test/coverage | 行为验证与真实覆盖率，按模块/任务缩小范围 |
| check | 静态检查、文档和架构约束 |
| gate/verify | 阶段证据检查与最终必需验证 |
| issue/issue-ui | 项目 Issue CLI 与独立静态页面 |
| clean | 只清理可重建产物，不删除任务、业务数据或未提交文件 |

按实际能力建立，不支持的目标不做假成功占位。Git 查询直接使用标准 Git，无需包装每个子命令。发布和提交不隐藏在普通构建或测试依赖中。

既有可靠脚本由 make 调用，对外文档和 CI 统一指向这些入口。help 与目标同步，可从注释生成。使用适当 .PHONY，传播失败退出码，保证依赖顺序；可写共享产物不得因 make -j 竞态。

参数按数据传递，验证标识、路径和枚举；Issue 标题、远端正文不得拼成 shell，禁止 eval。结果独立存放，清理后可重建；长服务显式启动结束，不藏进检查。遵循可用 Make/平台版本，跨平台差异由适配脚本处理。

README 记录实际命令与版本。首次接入检查 help、正常路径、失败传播和相关并发；没验证的目标注明。逐步统一入口而不重写可靠底层逻辑。普通任务遇到未接入 Make 的项目，先使用实际可靠的现有入口完成必要验证；适合本次范围时补相应 Make 包装，否则记录尚未统一的入口。完整入口迁移在 init/adopt 的授权范围内推进，不能因没有 Make 阻断修复。仅要求文档或只读分析时不顺便改整个构建系统。
