# 项目自己的 Issue 管理

本 skill 是指南。每个项目拥有自己的 Issue 数据、CLI、门禁和静态管理页面，不在 skill 目录或个人共享数据库集中保存项目业务。init/adopt 在获授权的项目内实现、测试并接入 Makefile，不能只交付概念演示。

## 目录与职责

结合已有项目调整；缺少等价结构时采用：

| 位置 | 职责 |
| --- | --- |
| `tools/dev/` | 项目开发管理 CLI、来源接入、HTML 模板和其测试；不属于产品运行代码 |
| `docs/issues/` | 本地权威 Issue 记录，默认每项一份结构化 JSON；索引由工具生成或查询 |
| 五类 docs | 需求、研究、设计、验证与来源；Issue 用相对路径关联 |
| `Makefile` | 用户、agent 与 CI 的共用操作入口 |

默认版本化保存脱敏后的 Issue。凭据、私密原文和大体积日志不提交。已有项目数据库可继续作为本地执行的权威存储，须说明备份、共享与恢复。SQLite 可作搜索索引；选择数据库为权威存储时由它负责同一组状态，不能存在两份可编辑权威记录。

明确字段归属：远端系统拥有其原始需求、评论和平台状态；项目内 Issue 拥有本次执行阶段、验收结果、验证、反思与待同步内容。本地需求文件保存带来源版本的执行解释，不能冒充远端已更新。项目已采用远端执行状态时，离线仅保存待同步变更与证据，不把它写成第二份已生效状态；恢复后先解决冲突。

工具不进入产品源码扫描、运行依赖、权限、资源打包或发布产物。不预建搜索索引、锁或缓存文件；确有需要时沿用项目已有约定。HTML 按需生成到项目已有输出目录，没有约定时使用系统临时目录，查看结束后清理。页面只读展示，使用本地资源，不注入应用路由、不依赖 CDN、不启动产品；写入由 CLI 完成后刷新页面。

## 稳定记录

任务标识不随标题、归档或合并改变。记录随阶段补齐，不预填尚未发生的测试或复审。基本字段包括种类、标题、输入摘要、日期；获授权的交付范围、操作边界与用户指令依据；来源实例/远端标识/URL/版本/同步基线/冲突；当前阶段、下一步和恢复条件；验收编号、需求版本引用及结果；docs、Git 提交/分支/PR 与未提交改动依据；实现/测试/复审身份和版本；检查与未解决发现；反思和知识落点；归档/合并/替代关系。

执行状态由 Issue 工具维护，文档不手工复制进度表。需求文件是本次产品范围与验收正文的唯一维护位置，每条验收使用稳定编号并关联文件版本或内容摘要；Issue 仅引用编号与版本，维护结果和证据，不保留另一份可单独编辑的验收正文。远端原文及其版本是来源快照，不自动替换本地执行解释。需求变化须重新核对相关验收与授权范围，使受影响结果失效，不能沿用旧完成状态。非需求任务按 [workflow](workflow.md) 保存自己的目标与完成证据，不机械新建产品需求。

尚未 init/adopt 的项目直接执行 research/run 时，先复用已有任务工具；没有工具则由单一协调者在项目内建立最小结构化记录，保存标识、种类、来源、授权范围、阶段、目标或验收引用、证据和下一步，继续原任务。不要为了一个 bug 顺带建设整套管理系统。完整 CLI/页面在获授权的初始化或接入中建立；随后导入原记录并保留标识，只保留一处可写状态。临时记录不是已经实现的 CLI。

## CLI 能力

命名可按项目调整，但须实现与测试。推荐 `make issue ARGS='list --json'`；参数按结构解析，禁止把外部正文拼接或执行为 shell 代码。

| 能力 | 要求 |
| --- | --- |
| create/update/show/list | 稳定编号、增量完善、状态查询、同来源去重 |
| search/recall | 中文、关键字、模块/状态/种类筛选；召回匹配经验与历史决定，返回依据，不虚构相似度 |
| note/reflect | 保存新证据和反思，不写逐轮聊天日志，不自动升为全局规则 |
| transition | 按 [workflow 的任务完成条件](workflow.md) 验证状态和适用门禁，不能任意写 done 或假造远端完成 |
| merge | 原子合并，原编号可追溯，保留来源、证据、历史；不直接合并验收通过状态 |
| compact | 核实摘要后精简，保留原依据和历史，不能丢未解决问题与限制 |
| archive/restore | 可逆管理可见性；归档不等于完成，合并项不能无说明变回重复活跃任务 |
| source/sync/resolve | 注册、验证、同步与冲突处理，不能覆盖未处理本地修改 |
| history/export/render | 查询历史、导出记录、生成只读页面，页面不另存业务状态 |

提供 JSON 与人可读输出、稳定错误码、长正文文件输入。写入用事务或可靠锁与原子替换，验证并发不丢数据，批量失败不留下半合并。保存成功但渲染失败须分别报告，页面可重新生成。

存储设计明确跨进程、worktree 和 clone 的协调范围：稳定编号采用能跨副本区分的身份，不靠每个副本各自加一；并发更新检查读取版本。文件存储的多记录合并需要事务日志或等价恢复机制，单次 rename 不能当作多文件事务。本地锁不保护其他机器；Git 合并后的任务状态冲突要明确解决，不能按文本自动合并就声称业务一致。项目应测试中断恢复和并发更新，而非只验证单进程正常路径。

## 自动记录与召回

在本项目提出实际需求、研究、bug 或明确长期反馈时，先查已有记录，再补充或创建并落地文档。普通问答不自动变为需求，建议标记待确认。开工按功能、模块、症状和相关提交召回，不把全部历史注入上下文。重复故障要检查原经验为何未生效：未读取、条件不清、缺检查或实现已变。

## 验证

独立测试持久化、来源去重、并发写入、中断恢复、中文搜索、空结果、非法状态、冲突、合并追溯、归档恢复、精简保留依据、门禁不可绕过及 HTML 不可信文本转义。测试数据隔离。模板、静态样例和手写输出不能称为可用系统。
