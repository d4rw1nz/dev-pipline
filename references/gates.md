# 交付检查

按 [任务类型与完成条件](workflow.md) 核实结果，使用项目已有测试、构建、静态检查和 CI。Issue 的头信息用于标明任务状态，验收依据来自实际执行结果。

## 检查内容

| 时机 | 核实内容 |
| --- | --- |
| 开始实现 | 目标、范围与完成条件清楚，影响实现的关键选择已确定 |
| 架构或接口调整 | 相关调用方、数据归属和历史原因已核实，方案解决实际问题 |
| 交付代码 | 必需检查已执行，结果对应当前相关代码与目标环境 |
| 完成任务 | 验收满足，复审发现已处理，文档一致，未验证项和限制已说明 |
| 外部回写或发布 | 有对应授权，实际结果已确认 |

研究、文档和审查任务使用各自适用的检查。必需验证失败或未执行时，保留未完成状态并说明原因。

## 执行与记录

- 核对命令的退出码与输出，失败传播非零。计数和覆盖率取自真实工具结果。
- 相关代码或需求变化后重跑受影响的检查。用提交号、必要的工作区说明和检查范围定位结果。
- 结果按 [验证材料的保存](documentation.md#验证材料的保存) 简记在同一 Issue 或交付回复中。
- 按 [验证规则](quality.md) 核实测试结果与复审发现，逐项确认实际完成情况。
- 单测行覆盖率以 80% 为目标。低于目标或未测量时说明范围与缺口，项目已有硬门槛时遵守该要求。

保留有效断言和业务代码的测试范围，如实说明失败、跳过与未执行项。已有无关失败单独说明，不降低项目现有要求。交付检查核实功能与验证结果，不要求专用 Issue 检查程序或额外报告文件。
