# 交付检查

按 [任务类型与完成条件](workflow.md) 核实实际结果，复用项目已有测试、构建、lint 和 CI。不为 Issue 建立状态转换程序、字段校验、内容哈希或证据登记系统，也不因缺少这些工具阻止正常开发。

## 需要核实的内容

| 时机 | 检查内容 |
| --- | --- |
| 开始实现 | 目标、范围与完成条件清楚；影响实现的未知选择已解决 |
| 架构或接口调整 | 相关调用方、数据归属与历史原因已核实，方案解决实际问题 |
| 交付代码 | 本次必需的测试和检查已执行，结果对应当前相关代码与目标环境 |
| 完成任务 | 验收满足，复审发现已处理，文档一致；未验证项和实际限制已说明 |
| 外部回写或发布 | 有对应授权，核实实际执行结果，不把本地完成当作远端完成 |

研究、文档和审查任务只使用适用检查，不套用代码覆盖率或构建要求。检查失败或必要验证未执行时如实报告，不能靠修改 Issue 状态宣布通过。

## 执行与记录

- 检查命令实际运行，核对退出码和输出；工具失败应传播非零。覆盖率和计数取自真实工具输出，不手填成功数字。
- 相关代码或需求变化后重跑受影响的检查；未变化部分不重复验证。用提交号、必要的工作区说明和检查范围定位结果，不为每次执行保存输入清单或哈希。
- 按 [验证材料的保存](documentation.md#验证材料的保存)，结果简要写回同一 Issue 或交付回复。需要临时文件时用系统临时目录，用完清理；不要求独立报告、日志文件或证据目录。
- 复审方式按 [quality](quality.md) 选择。独立测试设计不等于必须创建子 agent；实际执行与检查结果不能由自述“通过”代替。
- 80% 是单测行覆盖率目标，低于目标或未测量时说明范围与缺口；项目有明确硬门槛才按门槛执行，不为达标扩展无关改动。

不得删断言、隐藏失败、排除业务文件或不断重试制造通过。已有无关失败说明范围即可，不擅自降低项目现有检查要求。Issue 篇幅、文件数量、反思段落和固定标题都不作为完成条件。
